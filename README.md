# IMU Tracking Visualizer

Визуализация и анализ движений руки на основе данных IMU-датчика WitMotion WT9011DCL-BT50.
Приложение для изучения движений операторов хирургических роботов (консоль da Vinci).

**Стек:** React 19 · TypeScript · Vite · Three.js / @react-three/fiber · Recharts · FFT.js

---

## Входной формат

**Устройство:** WitMotion WT9011DCL-BT50 (9-DOF IMU, Bluetooth 5.0, 100 Hz)  
**Формат файла:** TSV, 27 колонок, разделитель — табуляция

| Колонка | Единицы | Описание |
|---------|---------|----------|
| time | `2026-3-25 0:12:55.983` | Абсолютная временная метка |
| AccX, AccY, AccZ | g | Линейное ускорение (включает гравитацию) |
| AsX, AsY, AsZ | °/с | Угловая скорость (гироскоп) |
| AngleX | ° | Roll — поворот ладонью вверх/вниз |
| AngleY | ° | Pitch — наклон пальцами вверх/вниз |
| AngleZ | ° | Yaw — поворот влево/вправо |
| Q0, Q1, Q2, Q3 | — | Кватернион ориентации (sensor fusion прошивки) |
| TrajectoryX/Y/Z | мм | Позиция из прошивки (только в Displacement mode) |

> **BLE-батчинг:** Bluetooth передаёт 4 семпла с одним таймстемпом. При `dt = 0` используется `dt = 0.01 с`.

## Вкладка «Motion» — анализ одной записи

### 3D Лента углов во времени
**Компонент:** `AngleRibbon3D` · Three.js  
Две ленты, развёрнутые вдоль оси времени: красная (Roll, вертикальная плоскость) и зелёная (Pitch, горизонтальная плоскость). Фиолетовая линия — комбинированный путь Roll × Pitch × Время.  
Нормализация: `Roll / 110 × 2`, `Pitch / 80 × 2`, `z = (t / tMax) × 3 − 1.5`.

---

### 3D След со временем
**Компонент:** `TipTrailTimeline3D` · Three.js  
Траектория «кончика» датчика, развёрнутая вдоль оси времени. Цветовой градиент зелёный→фиолетовый (начало→конец). Тень на полу + вертикальные соединители каждые 6 точек.  
Расчёт позиции кончика из кватерниона: `tipX = 2(q1·q3 + q0·q2) × 1.8`, `tipY = 2(q2·q3 − q0·q1) × 1.8`.

---

### 3D Углы Эйлера (Roll, Pitch, Yaw)
**Компонент:** `AngleTimeline` · Three.js  
Три параллельных «занавеса» углов во времени на отдельных вертикальных дорожках: Roll (красный), Pitch (зелёный), Yaw (синий).

---

### Профиль интенсивности движения
**Компонент:** `IntensityProfile` · Recharts LineChart  
Два ряда на одних осях:
- **Гироскоп** `√(AsX² + AsY² + AsZ²)` — суммарная угловая скорость (°/с)
- **Горизонтальное ускорение** `√(AccX² + AccY²) × 100` — линейное движение без гравитации  

Пики гиро = быстрые вращения, пики acc = ударные движения, плоские участки = паузы.

---

### Карта ориентации (Roll vs Pitch)
**Компонент:** `OrientationMap` · Recharts ScatterChart  
Scatter-диаграмма Roll × Pitch с цветовым кодированием по времени (зелёный→фиолетовый). Показывает «зону покрытия» — какие комбинации углов достигал оператор. Замкнутые петли = повторяющиеся движения.

---

### Фазовый портрет
**Компонент:** `PhasePortrait` · Recharts ScatterChart  
Диаграмма угол × скорость изменения угла (`rate[i] = Δangle / Δt`). Выбор оси: Roll / Pitch / Yaw. Замкнутые эллипсы = периодические движения, хаотичная форма = нерегулярные.

---

### Спектр тремора (FFT)
**Компонент:** `TremorSpectrum` · Recharts LineChart + FFT.js  
Спектральная плотность мощности гироскопа (AsX), метод Уэлча, окно 256 точек. Выделена зона физиологического тремора 8–12 Hz. Работает на полных данных 100 Hz без даунсемплинга.

---

## Вкладка «Tremor» — тремор-аналитика

Основана на алгоритмах из: *Gallego et al., "Real-Time Estimation of Pathological Tremor Parameters from Gyroscope Data", Sensors 2010.*

**Пайплайн:**
```
parseTsv() → t[], gyroX[]
  → criticallyDampedFilter()  → voluntary[]
  → tremor[] = gyroX[] − voluntary[]
  → wflc()                    → frequency[], amplitude_raw[]
  → kalmanAmplitude()         → amplitude[]
  → computeSpectrogram()      → power[freq][time]
```

---

### Разделение движений (CDF)
**Компонент:** `VoluntaryVsTremor` · Recharts LineChart  
**Алгоритм: Critically Damped Filter** — g-h трекер (θ = 0.990, g = 0.0199, h = 0.0001).  
Верхний график: raw (серый) + произвольное движение (красный). Нижний: изолированный тремор (синий).

---

### Мгновенная частота тремора
**Компонент:** `TremorFrequency` · Recharts LineChart  
**Алгоритм: WFLC** (Weighted Frequency Learning Controller, M=1, f₀=8 Hz, clamp 2–20 Hz).  
Цветные зоны: серая 0–2 Hz (произвольное движение), оранжевая 3–7 Hz (патологический тремор), голубая 8–12 Hz (физиологический тремор).

---

### Амплитуда тремора (Kalman)
**Компонент:** `TremorAmplitude` · Recharts AreaChart  
**Алгоритм: WFLC → Kalman-фильтр** (R = 0.01, Q = 0.001). Kalman точнее WFLC в 17 раз (FMSEd = 0.001 vs 0.017 рад/с).  
Показывает динамику тремора во времени. Покой ≈ 0 °/с, усталость → рост амплитуды к концу записи.

---

### Спектрограмма тремора
**Компонент:** `TremorSpectrogram` · HTML5 Canvas  
**Алгоритм: STFT** (Short-Time Fourier Transform). Окно 200 семплов (2 с), перекрытие 190, окно Ханна, диапазон 0–20 Hz.  
Тепловая карта мощности в dB, цветовая схема Inferno (фиолетовый→красный→оранжевый→жёлтый). Яркая горизонтальная полоса = устойчивый тремор на одной частоте.

---

## Вкладка «Comparison» — сравнение двух записей (DTW)

**DTW (Dynamic Time Warping)** — нелинейное выравнивание двух записей разной длительности, O(N×M).  
Реализовано по углам Эйлера: `d(i,j) = √((Roll₁−Roll₂)² + (Pitch₁−Pitch₂)²)` и по tip-позициям.

**Интерпретация нормализованного DTW (Euler):**
| Значение | Оценка |
|----------|--------|
| < 5 °/шаг | Отличная повторяемость |
| 5–20 °/шаг | Умеренные различия |
| > 20 °/шаг | Сильное расхождение |

---

### Roll во времени
**Компонент:** `RollComparison` · Recharts ScatterChart  
Наложение Roll двух записей на общую ось времени (красный / синий). Видна разница длительности, амплитуды и ритма.

---

### Траектории Roll vs Pitch
**Компонент:** `TrajectoryComparison` · Recharts ScatterChart  
Два облака Roll × Pitch наложены друг на друга. Разная форма = разный почерк оператора.

---

### DTW-матрица выравнивания
**Компонент:** `DtwAlignmentMatrix` · HTML5 Canvas  
Матрица стоимостей с оптимальным путём (золотая линия) и пунктирной диагональю идеального совпадения.  
Диагональный участок = синхронность, горизонтальный/вертикальный = одна запись «ждёт» другую.

---

### Tip-траектории (tipX vs tipY)
**Компонент:** `TipComparison` · Recharts ScatterChart  
Scatter-наложение траекторий кончика датчика двух записей в физическом пространстве.

---

### 3D-следы кончиков + DTW
**Компонент:** `TipTrailDtw3D` · Three.js  
Два 3D-следа, разнесённых по вертикали, соединённых полупрозрачными серыми нитями DTW. Короткие вертикальные нити = совпадение, длинные наклонные = расхождение. Камера управляется слайдерами yaw/pitch.

---

### 3D-ленты Roll + DTW
**Компонент:** `RollRibbonsDtw3D` · Three.js  
Две ленты Roll стоят рядом (красная и синяя) с заливкой к нулю. DTW-нити показывают выравнивание. Прямое сравнение формы и амплитуды.

---

### 3D Roll × Pitch × Время + DTW
**Компонент:** `OrientationDtw3D` · Three.js  
Самый информативный граф сравнения. Два пути в пространстве Roll × Pitch × Время с DTW-нитями.  
Вид сбоку = разница амплитуд, сверху = разница формы, спереди = хронологическое смещение.

---

## Архитектура

```
src/
  components/
    FileUploader/          — drag-and-drop TSV, парсинг в типизированный массив
    DataContext/           — глобальное состояние с данными датчика
    panels/                — 18 панелей визуализации (см. выше)
    layout/
      PanelGrid/           — разметка вкладок (Motion / Tremor / Comparison)
      VirtualCanvas/       — обёртка для 3D-холстов
    shared/
      PlaybackControls/    — управление воспроизведением
  utils/
    tsvParser.ts           — парсинг TSV → типизированные массивы
    quaternionMath.ts      — матрица вращения, tip-позиция
    signalProcessing.ts    — magnitude, производная, даунсемплинг
    tremorPipeline.ts      — CDF → WFLC → Kalman → STFT
    dtwAlgorithm.ts        — DTW O(N×M) с backtracking
    dtwPipeline.ts         — подготовка данных для сравнения
```

## Что работает и что нет

| Метод | Статус | Причина |
|-------|--------|---------|
| Кватернионы Q0–Q3 | **Работает** | Sensor fusion внутри прошивки, нет дрейфа |
| Углы Эйлера AngleX/Y | **Работает** | Прямо из прошивки, без интегрирования |
| Гироскоп AsX/Y/Z | **Работает** | Мгновенная угловая скорость |
| Позиция через ∫∫acc | **Не работает** | Ошибка O(t²): 0.002 g шума → 1.4 м за 13 сек |
| Displacement mode | **Не работает** | Гравитация протекает в X/Y при наклоне → сфера 2 м при вращении на месте |
